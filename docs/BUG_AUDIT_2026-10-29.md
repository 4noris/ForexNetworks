# RMS bug audit — 29 October 2026

## Fixed

- Native publication could raise `KeyError` when a new profile appeared before
  its financial row. Newly discovered profiles now participate in the account
  coverage check and merge. The previous verified generation remains visible
  while a bounded handoff completes.
- Replacing a native snapshot retained group financial aggregates, pending
  coverage state and the previous source clock. These now reset together, and
  the new snapshot's supplied server clock is retained.
- Exposure had no automatic query fallback when its subscription stayed silent.
  It now falls back after the initial stream grace period, retries bounded reads,
  cancels superseded reads and rejects older observations. Source interruptions
  preserve visibly delayed, dated data from the same scope.
- A second observer of an unchanged stream waited for a new data frame despite a
  verified cached snapshot being available. It now receives that snapshot when
  subscribing.
- A socket stuck in its opening handshake could remain `CONNECTING` indefinitely.
  The transport now closes an upgrade that has not opened within ten seconds and
  retries with its existing backoff.
- A conflicting historical archive caused repeated failing jobs and snapshot
  retries. The worker now shares a source check, reports the conflict once, and
  resumes if configuration becomes compatible. Historical report, export and
  manual-sync routes return an explicit 409 for a source conflict. Status and
  health remain available and identify the conflict. Existing records and source
  binding are preserved.
- Browser checks were still targeting the retired Analytics page, old Exposure
  transport and removed worst-positions table. They now verify the current
  Risk Center redirect, dedicated Exposure stream and complete virtualized book.
- The README's backend verification command now uses pytest, which loads the
  test database isolation in `tests/conftest.py` before importing the application.

- Frontend lint, native TypeScript contracts and production build: passed.
- Full desktop and mobile browser suite: 52 passed, 4 audit-login checks skipped.

- After restart, the current frontend build was served and 15 consecutive native
  readiness checks passed. Verified source age ranged from 1.453 to 5.237 seconds.
  The new runtime log contained no tracebacks or native publication errors, one
  archive conflict notice, and no repeated failed historical jobs.

Browser data is mocked or computed from test-only fixtures. No real client push
notifications, Telegram alerts or trades were sent for validation. Live
authenticated tests require a separate audit login and are skipped when no audit
credentials are configured. The public readiness check validates native source
availability separately; it does not establish live browser transport latency.

## Remaining source limitation

The deployment's existing historical archive belongs to a different Manager
source. Its records cannot establish history for the current source. A compatible
archive/database configuration or deliberate migration is required to resume
those historical reports; the audit does not delete, rebind or mix that archive.
No claim of millisecond end-to-end freshness or absence of all possible defects
is made by these checks.
