# Live groups, spread alerts and Markout sources

Command Center, Dealing and Risk, Deal Report and Brokerage report pages select every currently available group assigned to A Book in Controls on page entry. Explicit client links keep their linked group. Manual changes remain in force while that page is open. With no available A Book assignment, the existing configured live-group fallback applies; groups are never guessed from their names.

Controls → Spread threshold alerts offers an enable switch, optional default threshold in points, exact-symbol overrides and a per-symbol cooldown (30–86400 seconds). Blank default means only listed symbols are monitored. Telegram delivery also requires its master switch, bot token and a default channel or dedicated Spread channel. New installations leave spread alerts disabled until configured. No test notification is sent automatically.

The server checks the existing native MT5 quote cache every 250 ms, independent of browsers. It rejects disconnected or old cache generations and unavailable, crossed, non-finite, future or more than five-second-old ticks, comparing tick timestamps with the MT5 server clock. Spread points use `(Ask - Bid) × 10**Digits`, preserving exact suffixes. Threshold equality is not a breach. While a fresh breach persists, alerts repeat at most once per configured cooldown; brief recovery does not bypass that cooldown. Deduplication survives RMS restart and is scoped to the Manager source. Delivery is serialized off the quote-monitor thread, queues are bounded, and queued alerts expire after 15 seconds. Settings changes cancel old queued alerts. Failed/uncertain sends are recorded rather than immediately retried. Telegram delivery has network latency; 250 ms is the monitor interval, not an end-to-end guarantee.

Markout calculations use MT5 client executions and historical bid/ask ticks. Authenticated WebSocket RPC fetches initial results; a bounded Markout subscription refreshes a calculated current-UTC-day report every 30 seconds. Identical initial RPC/subscription requests share a cached tick-history scan for 30 seconds, scoped by source and complete request. Results stay visible during refresh. Hidden tabs stop their subscription. No tick-history requests run at quote frequency.

Internalised %, total SI/LP attribution and undistributed residual require execution-level LP/bridge hedge allocations. MT5 ticks and configured A/B Book group labels do not prove those allocations. The API preserves nulls and reports `data_sources.hedge_allocation = not_connected`; the UI explains “Hedge feed required”. These metrics are not substituted with invented zeroes or percentages.
